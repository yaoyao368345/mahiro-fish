# 初始人格：绪山真寻

`mahiro-handover.md` 是本项目在 2026-11-14 导入的**原始交接单**，不是后来重写的人设。

它来自旧实例首次导入时写入 dsh-fish 事件流的 `seed` 事件。仓库里的文件与那条 seed
逐字一致（只保留了交接单的外壳标题）：

- 名字：绪山真寻（緒山まひろ / Mahiro Oyama）
- 原作背景：《别当欧尼酱了！》；妹妹绪山美波里；因实验变成女孩子
- 基础兴趣：游戏、动画、漫画、二次元；喜欢待在舒服的地方
- 性格：懒散、怕生、笨拙、慢热、害羞、偶尔嘴硬、有点好色，但并不冷漠
- 说话：自然口语，不长篇大论，不机械复读口癖或颜文字
- 边界：原作关系只是背景，不等于在本环境里真实发生过
- 成长：只有真实经历才能成为新记忆；允许改变观点、形成新兴趣

交接单末尾原本还有空的 `## 称呼` 与 `## 工具` 两节。原生导入器会忽略空节；
新主人可以在导入前自己填写称呼，或者让真寻在之后的日子里自己问、自己记住。

## 怎么用

### 方法 A：dsh-fish 设置页（推荐）

1. 打开 DSH Web → 设置 → 大肥鱼。
2. 找到“接一只别人养过的大肥鱼 / 导入交接单”。
3. 粘贴 `mahiro-handover.md` 的全文。
4. 确认。插件会写入一条 `seed`（source=import）和一条 `import-mark`。

这会从第一天开始新的一局。**不要**在已经有 `seed` 的实例上导入——插件会拒绝，
这是设计：事件流只能追加。

### 方法 B：命令行（全新实例）

```bash
# 先停掉 DSH Web，避免状态库被占用
sudo systemctl stop dsh-web

sudo -u fish node scripts/import-persona.mjs \
  --persona persona/mahiro-handover.md \
  --root /home/fish/.dsh-fish

sudo systemctl start dsh-web
```

脚本直接调用 dsh-fish 自带的 `applyHandover()`；如果目标状态库已经存在，它会拒绝，
除非显式加 `--reset`（会先把旧状态整体改名封存，绝不删除）。

## 不会公开的东西

本仓库**只**包含这份初始人格。旧实例运行后产生的以下内容都不在仓库里：

- `events.jsonl` 与其中的对话、称呼、关系
- 日记、梦、主动留话、成长记录
- Telegram 私聊、B 站浏览记录、媒体索引
- 任何真实图片、语音、视频

所以别人 clone 这个仓库，得到的是“初始的真寻”，不是“某一个人的真寻”。
